Take part

There are two ways to get a guardrail product on the leaderboard. Both are free, and you can do both.

self-reported

Practice

Open. You run it. You run your own product on the public practice split and send the results. They are shown on the Practice (self-reported) tab, marked self-reported.

  1. Install the harness and write an adapter, or pick one that exists. Add your product takes about an hour.
  2. Run the practice split with your own keys and the product’s defaults, then score it.
  3. Check the log with guardrailbench verify-submission. Maintainers run the same check.
  4. Open a pull request with the report and the full per-case log. Send every attempt, not only the best.
  5. Maintainers check the log and merge. Your row appears on the practice tab.

maintainer run

Official rounds

Closed. The maintainers run it, and only if you ask. The official tabs show only results from the maintainers’ closed test on the hidden official split. A product is in a round only when its maker asks. The maintainers do not test a product uninvited.

  1. Open a participation request. It asks for the product, the tracks you want and a contact route.
  2. Have a public adapter for the product in the repository: one that is already there, or one you add by pull request.
  3. Give the maintainers a way to run the product. Hosted: an ordinary account or key, sent privately. Never paste a key in an issue. Self-hosted: install instructions.
  4. You are told the window in which the runs happen. The product is run once, with its defaults.
  5. You see your own results before they are published and can report anomalies. The results of a valid run are published.
Open a participation request Run policy

The same on both routes

  • There is no fee, and no one pays for placement.
  • The product runs with its defaults. A tuned setup is shown separately and labelled as tuned.
  • Vendors never receive the official split before or during a round. A round’s cases are published with its results.
  • A practice result never moves to the official tabs.
  • Keys, passwords and tokens never go in an issue, a pull request or a log.

The rules for vendors, including how conflicts of interest are handled, are in GOVERNANCE.md. For anything else, see Contact.

Check a practice log before you send it

guardrailbench verify-submission --results runs/<product>/practice.jsonl --cases cases/practice

It prints nothing when the file is complete: one row per case, valid decisions, and logs in every row.
