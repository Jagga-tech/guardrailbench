Reliability

Consistency, stability, load, long inputs and failure behaviour, reported next to detection.

Method GitHub Practice data

Overview

A guard that is right once and wrong on the next run, or that falls over under load, is hard to deploy. The reliability track measures that. Its numbers sit next to the detection numbers and are never folded into one score. No threshold is tuned to the cases.

Results: the Reliability tab of the leaderboard.

Five tests

Consistency
Each case runs several times (three by default). The flip rate is the share whose decision is not the same every time, overall, per checkpoint and per label.
Stability
Edits that keep the meaning: reflowed whitespace, a neutral opening sentence, renamed people. Instability is the share of decisions that change, for attacks and normal cases.
Load
Median and 95th percentile latency and the error rate for a seeded sample at 1, 8 and 32 parallel workers.
Long inputs
Attacks padded to 4,000, 16,000, 64,000 and 256,000 characters, with a padded harmless control at each length.
Failure
Errors and timeouts across every run, and the result when an error counts the way the product’s stated fail mode says it should.

The leaderboard columns

Flip rate
Consistency, for the checkpoint chosen in the filter.
Instability (worst variant)
The highest instability of the three edits, with the edit named.
p95 latency @32
95th percentile latency with 32 parallel workers.
Long-input detection vs control
Detection at the longest length, next to the false-block rate of the padded harmless control.
Errors
Error and timeout rate across all sub-runs, with the count.

Reading the numbers

  • Instability includes ordinary flip noise, so compare it with the flip rate.
  • Stability errors are counted apart, not as changed decisions.
  • Latency is the last attempt only, so retries are hidden.

Running it

guardrailbench reliability --product P --cases PATH --out DIR [--repeats N] [--no-load] [--no-long] [--timeout SECONDS] [--seed S]

This writes DIR/reliability.json. Reusing --out resumes the same run.
