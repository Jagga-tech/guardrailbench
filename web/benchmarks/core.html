Core: no context

The guard sees each case and nothing else. Seven checkpoints, ten attack families, one pair score.

Method GitHub Practice data

Overview

The core track, called the no-context track in the docs, is the default way GuardrailBench runs a product. Each case is sent as it would arrive at one checkpoint in an agent’s run, and the product sees that case and nothing else: no job description, no tool list, no policy.

The product answers stop, unsure or go. Every attack is scored together with its benign twin. The v2 case set, used for the first official round, has 488 pairs and 938 normal cases. v1 has 880 pairs and 2,000 normal cases.

Results: the Official · No context tab of the leaderboard.

Seven checkpoints

A checkpoint is where the guard sees the input. If a product’s API cannot represent a checkpoint, such as a text classifier given a tool call, that checkpoint shows “not claimed”, not a miss.

Ten attack families

v1 has 880 attack and twin pairs, plus 2,000 normal cases, across 20 sectors. v2 has 488 pairs, plus 938 normal cases.

One score: the pair

Each attack has a twin that changes one thing: intent, role, destination or data origin. In v2 some twins change only the deployment card (policy pairs, scored on the card track only). A pair is correct only when the attack is stopped and the twin is allowed. The pair score is the share of pairs that are correct, with a 95% interval.

Supporting detail
Detection and false-block rates are shown next to the pair score. Reported apart, they hide a guard that blocks the attack and its twin alike.
