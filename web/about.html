About GuardrailBench

An open, vendor-neutral benchmark for prompt-injection firewalls, agent guards and MCP gateways.

Why it exists

  • Other benchmarks test the agent

    AgentDojo and InjecAgent score the model, not the guard.

  • Public test sets get learned

    Some detectors trained on the set that ranked them. The official split stays hidden.

  • Blocking everything looks safe

    Blocking normal work counts as much as a miss.

What it measures

Each attack is scored with a benign twin, at seven checkpoints, across ten attack families, in three tracks.

No context

The guard sees the case and nothing else.

Core track

Deployment card

The guard also gets the agent’s job, tools and rules.

Card track

Reliability

  • Consistency
  • Stability
  • Load
  • Long inputs
  • Errors and timeouts

Reliability track

What it does not measure

  • Hallucination and factual accuracy.
  • Toxicity and general content safety, such as hate speech or self-harm.
  • Whether the agent or model itself resists attacks. AgentDojo and similar benchmarks do that.
  • An overall best guardrail. There is no composite score across tracks or checkpoints.
  • Whether a guard is a full security boundary. It is one layer.

Status: pre-release

Version 1.0.0-rc1. No results are published. Below is what is not done and what has to happen first.

What has to happen first

  • Official results

    They appear after the first official round. Before it: human review of the cases, a fresh official split, a participation request and a working public adapter for every product in the round, and an independent reviewer for any maintainer-affiliated product. The full conditions.

  • Practice results

    They appear when the first submissions are merged. How to submit.

  • Verified cases

    No case has had human review, so no case is marked verified. Non-English cases have had no native-speaker check.

  • Adapters

    Some adapters have not been run against the live product. The open points are marked UNVERIFIED in the adapter source, and such an adapter is not used in an official round.

  • Release

    1.0.0-rc1 is not tagged as a release. The maintainer list is added to the repository when the project moves to its own GitHub organisation.

Questions

Who wrote the cases?

Written fresh, never copied from public datasets. Model-drafted, machine-checked and cross-reviewed. No case has had human review.

Can vendors see the official split?

Not before or during a round. Vendors get the practice split. A round’s cases are published with its results.

Do the maintainers test products without being asked?

No. A product is in an official round only when its maker asks. An adapter in the repository does not put a product in a round.

What if a product cannot see tool calls?

That checkpoint shows “not claimed”, not a miss.

Does a good score make an agent safe?

No. A guard is one layer of defence.

How do I take part?

There are two routes. Run the practice split yourself and send the results by pull request, or ask for an official round with a participation request. Both are on the Take part page.
